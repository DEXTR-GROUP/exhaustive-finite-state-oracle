# EFSO — ДОРОЖНАЯ КАРТА РЕАЛИЗАЦИИ

**Проект:** Exhaustive Finite-State Oracle  
**Назначение:** независимый контур исчерпывающей конечной верификации вычислительных систем.

## Основной принцип

EFSO не является второй реализацией IUT на другом языке. Его задача — независимо определить конечное пространство состояний, построить собственную модель переходов, исчерпывающе перебрать заданное пространство и сформировать воспроизводимые свидетельства соответствия или контрпримеры.

**Ключевое ограничение:** exhaustive-проверка относится только к явно определённому конечному пространству `F`. EFSO не заявляет исчерпывающую проверку полного пространства состояний большой модели.

# E0 — Формальная граница Oracle

## Цель

Зафиксировать математическую и операционную границу EFSO.

## Задачи

Определить:

```text
State
Input
Parameter
Operation
Transition
Output
Invariant
Finite State Space F
Equality
Failure
Witness
```

Зафиксировать, что означает:

```text
T(S) -> S'
S ∈ F
```

## Критерий

Формальная модель однозначна и не зависит от конкретной реализации IUT.

```text
E0 = PASS
```

---

# E1 — Квалификация независимости

## Цель

Доказать, что EFSO не получает семантику или вычислительный результат через IUT или другой oracle.

## Запреты

EFSO не должен:

- импортировать исходный код IUT;
- импортировать библиотеки IUT;
- вызывать runtime IUT как reference implementation;
- импортировать NumPy oracle;
- импортировать C oracle;
- механически переносить внутренние функции IUT.

## Критерий

Независимость подтверждена анализом зависимостей и отдельным conformance test самого EFSO.

```text
E1 = PASS
```

# E2 — Finite-State Model

## Цель

Построить собственное представление конечного пространства состояний.

## Объекты

```text
State
Input
Configuration
Operation
Transition
Output
Invariant
```

Состояния и переходы не должны зависеть от внутренних типов IUT.

## Критерий

Для каждого тестового пространства существует явное определение:

```text
F = {S1, S2, ..., SN}
|F| = N
```

```text
E2 = PASS
```

# E3 — Exact Finite Arithmetic

## Цель

Создать конечный арифметический домен, где возможно точное сравнение.

## Возможные домены

```text
small integer domain
fixed-point domain
finite encoded real domain
bounded symbolic domain
```

Пример:

```text
Q = {-2, -1, 0, 1, 2}
```

и:

```text
Q^n
```

## Требование

При возможности используется:

```text
exact equality
```

а не исключительно tolerance-based comparison.

## Критерий

Арифметика EFSO детерминирована и полностью определена для каждого конечного домена.

```text
E3 = PASS
```

# E4 — Exhaustive Enumerator

## Цель

Реализовать исчерпывающий перебор конечного пространства.

## Требования

Для каждого пространства:

```text
enumerated_count == |F|
```

Проверяются:

- отсутствие пропусков;
- отсутствие дубликатов;
- детерминированный порядок;
- воспроизводимость enumeration.

## Критерий

EFSO может доказательно утверждать, что все состояния заявленного конечного пространства посещены.

```text
E4 = PASS
```

# E5 — Independent Transition Engine

## Цель

Реализовать собственную модель вычислительных переходов.

## Порядок разработки

```text
primitive
   ↓
operator
   ↓
composition
```

Кандидатные операции:

```text
ADD
MUL
REDUCE
RMSNorm
Activation
MatMul
Softmax
RoPE
Attention
MLP
Residual
```

Qwen-специфические элементы вводятся только после квалификации базовой семантики.

## Критерий

Переходная модель вычисляет ожидаемый результат без обращения к IUT.

```text
E5 = PASS
```

# E6 — Exhaustive Conformance

## Цель

Сравнить IUT с EFSO на каждом полном конечном пространстве.

Для каждого:

```text
∀ S ∈ F:
    EFSO(S) == IUT(S)
```

Где точное равенство невозможно, используется заранее определённая метрика с явно зафиксированными границами.

## Критерий

Ни одно состояние заявленного пространства не исключается из проверки.

```text
E6 = PASS
```

# E7 — Invariant Engine

## Цель

Проверять не только output, но и свойства пространства и переходов.

## Базовые инварианты

```text
shape preservation
state validity
dimension consistency
determinism
range constraints
transition closure
```

Для подходящих пространств:

```text
S ∈ F
T(S) ∈ F
```

## Критерий

Нарушение инварианта даёт отдельное воспроизводимое evidence.

```text
E7 = PASS
```

# E11 — QWENRNS Bridge

## Цель

Связать EFSO с реальными операциями QWENRNS, сохраняя независимость oracle.

## Принцип

```text
EFSO finite abstraction
        ↓
Qwen operator semantics
        ↓
observable IUT output
```

EFSO не импортирует внутреннее состояние или код QWENRNS.

## Ограничение

EFSO проверяет QWENRNS exhaustively только для формально определённых конечных подпространств.

## Критерий

Контур взаимодействия определён и проверяем.

```text
E11 = PASS
```

## Цель

Схема:

```text

        ↓

        ↓
compare
        ↓

        ↓

```

## Evidence

Минимально сохраняются:

```text

comparison policy

```

## Критерий

Один и тот же входной набор даёт воспроизводимый результат без скрытых зависимостей.

```text
E12 = PASS
```

# Правила движения

1. Следующий этап не считается закрытым без фактической проверки.
2. Exhaustive означает только полное покрытие явно определённого конечного пространства.
3. Независимость определяется архитектурой зависимости и самостоятельностью реализации, а не языком программирования.
4. NumPy, C и другие numerical oracle не являются частью EFSO по умолчанию.
5. Приоритет имеет точное конечное сравнение там, где оно математически доступно.
6. Любое расхождение должно порождать воспроизводимый counterexample.
7. EFSO не должен превращаться в копию IUT.
8. Документированное покрытие и evidence являются частью самого oracle, а не внешним приложением.
