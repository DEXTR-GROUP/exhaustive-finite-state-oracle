# EFSO — ТЕКУЩЕЕ СОСТОЯНИЕ

**Идентификатор:** EFSO-STATE-001  
**Статус:** В РАБОТЕ

## 1. Рабочая граница

Проектирование и последующая реализация независимого `Exhaustive Finite-State Oracle` для исчерпывающей проверки явно определённых конечных пространств состояний и переходов.

## 2. Подтверждено

- создан отдельный репозиторий EFSO;
- определено назначение EFSO как независимого verification-контура;
- создана дорожная карта реализации EFSO;
- зафиксировано ограничение exhaustive-проверки конечным пространством `F`;
- определены контрольные вехи FM0–FM12;
- создан нормативный Journal EFSO;
- NumPy, C и другие внешние numerical oracle не являются частью EFSO по умолчанию;
- EFSO не должен зависеть от IUT.

## 3. Незавершено

- формальная спецификация пространства состояний;
- независимая модель переходов;
- конечная арифметика;
- exhaustive enumerator;
- invariant engine;
- counterexample engine;
- conformance harness;
- qualification независимости;
- интеграционный bridge к IUT.

## 4. Блокирующие условия

Реализация EFSO не должна начинаться с копирования внутренней архитектуры IUT. Сначала должны быть определены нормативные границы и независимая модель.

## 5. Следующая контрольная точка

**FM0 — Formal Boundary**

Цель: формально определить State, Input, Parameter, Operation, Transition, Output, Invariant, конечное пространство `F`, правила equality/failure и формат witness.

Условие закрытия:

```text
E0 = PASS
```

и имеется самостоятельное нормативное описание, достаточное для реализации без обращения к внутренним типам IUT.

## 6. Текущее направление

```text
Journal / нормативная база
          ↓
FM0 — Formal Boundary
          ↓
FM1 — Independence
          ↓
FM2 — Finite-State Model
          ↓
FM3 — Exact Arithmetic
          ↓
...
          ↓
FM12 — Verification Harness
```

Реализация выполняется отдельным рабочим этапом в другом диалоговом окне после завершения подготовки нормативной базы.
