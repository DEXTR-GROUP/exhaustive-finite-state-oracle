# EFSO — МАЯК

**Идентификатор:** EFSO-MAIAK-001  
**Статус:** КАНОНИЧЕСКИЙ  
**Тип:** НОРМАТИВНАЯ ОПЕРАЦИОННАЯ МОДЕЛЬ

## 1. Назначение

МАЯК является единственной оперативной точкой ориентации проекта. Он фиксирует фактическое состояние, текущую рабочую границу, блокировки и одну ближайшую проверяемую контрольную точку.

МАЯК не является дорожной картой, спецификацией, журналом истории или доказательством сам по себе.

## 2. Основной принцип

```text
фактическое состояние
        ↓
текущая контрольная точка
        ↓
проверка
        ↓
закрытие / блокировка
        ↓
следующая контрольная точка
```

Непроверенное изменение не становится новым подтверждённым состоянием.

## 3. Что фиксируется

МАЯК должен содержать:

- текущий статус;
- текущую рабочую границу;
- последнее подтверждённое состояние;
- незавершённые вопросы;
- блокирующие условия;
- одну ближайшую контрольную точку;
- условия её закрытия;
- последний существенный результат;
- следующий обязательный шаг.

## 4. Статусы

Допустимы:

```text
ПЛАН
В РАБОТЕ
НА ПРОВЕРКЕ
ЗАБЛОКИРОВАНО
ПОВТОРНАЯ ПРОВЕРКА
ГОТОВО
```

Статус выбирается по evidence, а не по намерению.

## 5. Правила движения

1. Нет проверки — нет закрытия.
2. Нет подтверждения — нет нового базового состояния.
3. У проекта одна основная ближайшая контрольная точка.
4. Блокировка имеет приоритет над последующими этапами.
5. Неудача оставляет контрольную точку незакрытой.
6. Существенный новый дефект отражается в МАЯКе.
7. История не переписывается.
8. Статус не может быть сильнее имеющегося evidence.

## 9. Перенос между диалогами

Диалог не является источником истины. Новый рабочий контекст восстанавливается в порядке:

```text
МАЯК
 ↓
main / commit
 ↓
CI / evidence
 ↓
нормативные документы
 ↓
следующий шаг
```

При конфликте приоритет имеет фактическое состояние репозитория и воспроизводимое evidence.

## 10. Инварианты

МАЯК должен сохранять:

- фактическое состояние вместо предположения;
- видимую блокировку;
- одну основную ближайшую контрольную точку;
- связь с evidence;
- непротиворечивость с `main`.

Изменение модели МАЯКА допускается только как отдельное нормативное изменение, если практика выявила универсальную проблему модели.
