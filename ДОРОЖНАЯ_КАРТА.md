# EFSO — ДОРОЖНАЯ КАРТА РЕАЛИЗАЦИИ

**Проект:** Exhaustive Finite-State Oracle  
**Назначение:** независимый контур исчерпывающей конечной верификации вычислительных систем.

## Основной принцип

EFSO не является второй реализацией IUT на другом языке. Его задача — независимо определить конечное пространство состояний, построить собственную модель переходов, исчерпывающе перебрать заданное пространство и сформировать воспроизводимые свидетельства соответствия или контрпримеры.

**Ключевое ограничение:** exhaustive-проверка относится только к явно определённому конечному пространству `F`. EFSO не заявляет исчерпывающую проверку полного пространства состояний большой модели.

**Новый квалификационный принцип:** существующие независимые numerical oracle QWENRNS (`R4 → R5 → R6 → R7 → NumPy float64`) используются как внешние qualification witnesses для EFSO. Они не становятся зависимостями EFSO и не определяют его собственную exhaustive-семантику.

```text
QWENRNS independent references
        │
        ▼
   FM0–FM3 qualification boundary
        │
        ▼
       EFSO
        │
        ▼
 exhaustive structural verification
```

Отдельный C `float64` oracle на текущем этапе **не требуется**: NumPy `float64` уже предоставляет независимую numerical reference axis. При этом `float64` не трактуется как exact real arithmetic.

# FM0 — Formal Boundary

## Цель

Зафиксировать точную границу EFSO qualification и определить, что именно подтверждается внешними reference oracle, а что должно быть доказано самим EFSO.

## Квалифицируемый объект

EFSO получает:

```text
FiniteStateSpace
InitialState
TransitionRelation
EvaluationFunction
```

и формирует:

```text
EnumeratedStates
Transitions
Evaluations
Trace
Cardinality
Digest
```

## Qualification Case

Каждое внешнее испытание должно иметь машиночитаемое описание:

```text
QualificationCase {
    case_id
    reference_id
    finite_state_model
    initial_state
    input_encoding
    expected_cardinality
    reference_outputs
    comparison_policy
    expected_trace_properties
    expected_digest
}
```

Базовые qualification cases:

```text
EFSO-Q-R4
EFSO-Q-R5
EFSO-Q-R6
EFSO-Q-R7
EFSO-Q-NP64
```

## Что квалифицируют R4–R7 и NumPy

Они могут подтверждать соответствие EFSO независимой reference semantics на явно определённых конечных пространствах:

```text
EFSO(state) ↔ independent reference(state)
```

Но они **не доказывают сами по себе**:

```text
exhaustiveness
absence of omitted states
absence of duplicate states
cardinality correctness
deterministic enumeration
replay correctness
universal applicability of EFSO
```

Эти свойства относятся к внутренней доказательной части EFSO.

## Критерий

Граница ответственности формально зафиксирована; numerical qualification и structural exhaustive proof не смешиваются.

```text
FM0 = PASS
```

# FM1 — Independence Qualification

## Цель

Подтвердить, что внешние reference oracle действительно независимы от EFSO и что EFSO не получает ожидаемые результаты из них во время своей собственной работы.

## Запреты внутри EFSO

EFSO не должен:

- импортировать исходный код IUT;
- импортировать библиотеки IUT;
- вызывать runtime IUT как reference implementation;
- импортировать R4/R5/R6/R7 oracle;
- импортировать NumPy oracle;
- механически переносить внутренние функции IUT или reference oracle.

**Важно:** qualification harness может запускать внешние oracle и сравнивать их результаты с результатами EFSO. Это внешний контур квалификации, а не зависимость EFSO.

## Независимые вычислительные пути

```text
R4  — primitive Attention reference
R5  — independent MLP reference
R6  — independent Transformer Block reference
R7  — independent end-to-end forward reference
NP64 — independent NumPy float64 reference
```

## Dependency Audit

Для каждого qualification case формируется:

```text
dependency_manifest.json
```

Минимальные поля:

```text
case
reference
imports_efso
calls_efso
uses_efso_types
uses_efso_constants
uses_efso_outputs
```

Все зависимости от EFSO должны быть `false`.

## Mutation Independence

Qualification harness должен проверять, что преднамеренная мутация EFSO не изменяет внешний expected result:

```text
skip state
create duplicate
alter transition
alter arithmetic
alter enumeration order
```

Если изменение EFSO изменяет reference expectation, независимость считается нарушенной.

## Критерий

Независимость EFSO и внешних reference подтверждена структурным audit и mutation independence test.

```text
FM1 = PASS
```

# FM2 — Finite-State Qualification Model

## Цель

Преобразовать R4 → R5 → R6 → R7 → NumPy float64 в формально определённые конечные qualification spaces, которые EFSO способен исчерпывающе перебрать.

## Общая модель

Для каждого case определяется:

```text
F = finite state space
I = initial state
T = transition relation
V = evaluation function
```

Требуется:

```text
F = {S1, S2, ..., SN}
|F| = N
```

и независимое описание domain каждого параметра.

## R4 — Attention

Минимальное конечное пространство для primitive Attention.

Проверяется:

```text
state identity
input domain
attention parameters
scores
normalization
weighted value output
```

R4 является первым qualification layer для базовой numerical semantics.

## R5 — MLP

Конечное пространство для gated MLP:

```text
input
up weights
 gate weights
down weights
biases
```

Все параметры должны иметь явно ограниченный finite domain.

R5 квалифицирует нелинейную и gated composition.

## R6 — Transformer Block

Конечное пространство объединяет последовательность:

```text
RMSNorm
   ↓
MLP
   ↓
Residual
```

EFSO должен представлять промежуточные состояния и переходы, а не только конечный output.

## R7 — End-to-End Forward

Основной композиционный qualification case:

```text
Embedding
 ↓
RMSNorm
 ↓
Q/K/V
 ↓
RoPE
 ↓
Causal Attention
 ↓
O projection
 ↓
Residual
 ↓
Post-Norm
 ↓
Gated MLP
 ↓
Layer 2
 ↓
Final RMSNorm
 ↓
Logits
```

Используется малое полностью обозримое пространство, соответствующее существующему независимому R7 reference.

Базовая конфигурация:

```text
seq = 2
hidden = 4
intermediate = 3
heads = 2
kv_heads = 1
head_dim = 2
vocab = 5
```

## NumPy float64

Для того же или специально определённого finite state space запускается независимая numerical reference в `float64`.

Цель:

```text
same state
    ├── EFSO / implementation arithmetic
    └── NumPy float64 reference
```

Измеряется numerical divergence.

**Ограничение:** NumPy `float64` устраняет только один класс finite-precision effects и не является exact real arithmetic oracle.

## Критерий

Для каждого qualification case существует явное finite-state definition, ожидаемая cardinality и независимая evaluation semantics.

```text
FM2 = PASS
```

# FM3 — Exact Structural Model

## Цель

Разделить свойства, которые должны проверяться точно, от численных свойств, для которых используется независимая reference arithmetic.

## Exact State Identity

Каждое состояние должно иметь каноническое представление:

```text
canonical_encode(state)
state_id = H(canonical_encode(state))
```

Требуется:

```text
state_a == state_b
↔
canonical_encode(a) == canonical_encode(b)
```

State identity не должна зависеть от:

```text
memory address
allocator
process
enumeration order
platform-specific object identity
```

## Exact Cardinality

Для каждого qualification space фиксируется:

```text
expected_count
observed_count
unique_count
missing_count
duplicate_count
```

Необходимые условия:

```text
observed_count == expected_count
unique_count   == expected_count
missing_count  == 0
duplicate_count == 0
```

## Exact Transition Structure

Для каждого перехода сохраняются:

```text
source_state_id
transition_id
target_state_id
```

Должна быть воспроизводима последовательность:

```text
state
 → operation
 → next state
 → evaluation
```

## Exact Structural Arithmetic

Точно проверяются там, где это математически возможно:

```text
integer state indices
finite-domain values
cardinality
state IDs
transition IDs
configuration masks
enumeration counters
```

## Numerical Arithmetic

Для операций, не имеющих практического exact representation в данном qualification contour:

```text
exp
SiLU
softmax
matrix multiplication
RoPE
normalization
attention
MLP
```

используется заранее определённая независимая reference arithmetic.

Таким образом:

```text
structural correctness = exact
numerical conformance  = reference-qualified
```

## Критерий

Структурная модель EFSO exact и детерминирована; numerical conformance явно отделён от claim об exact real arithmetic.

```text
FM3 = PASS
```

# E4 — Exhaustive Enumerator

## Цель

Реализовать исчерпывающий перебор конечного пространства.

## Требования

Для каждого пространства:

```text
enumerated_count == |F|
```

Проверяются:

- отсутствие пропусков;
- отсутствие дубликатов;
- детерминированный порядок;
- воспроизводимость enumeration.

## Критерий

EFSO может доказательно утверждать, что все состояния заявленного конечного пространства посещены.

```text
E4 = PASS
```

Реализовать собственную модель вычислительных переходов.

## Порядок разработки

```text
primitive
   ↓
operator
   ↓
```

```text

MUL
```

## Критерий

Переходная модель вычисляет ожидаемый результат без обращения к IUT или внешнему oracle во время исполнения EFSO.

```text
E5 = PASS
```

# E6 — Exhaustive Conformance

## Цель

Сравнить IUT с EFSO на каждом полном конечном пространстве.

Для каждого:

```text
∀ S ∈ F:
    EFSO(S) == IUT(S)
```

Где точное равенство невозможно, используется заранее определённая метрика с явно зафиксированными границами.

В qualification contour допускается дополнительное независимое сравнение:

```text
EFSO(S) ↔ R4/R5/R6/R7(S)
EFSO(S) ↔ NumPy_float64(S)
```

При этом external reference остаётся witness, а не частью EFSO runtime.

## Критерий

Ни одно состояние заявленного пространства не исключается из проверки.

```text
E6 = PASS
```

```text
E7 = PASS
```

# E11 — QWENRNS Qualification Bridge

## Цель

Связать EFSO с существующим независимым numerical validation contour QWENRNS, не превращая QWENRNS в runtime dependency EFSO.

## External qualification sequence

```text
R4
 ↓
R5
 ↓
R6
 ↓
R7
 ↓
NumPy float64
```

Каждый reference проходит через FM0–FM3 и используется как независимый qualification witness.

## Принцип

```text
QWENRNS reference
        ↓
qualification harness
        ↓
EFSO
```

а не:

```text
EFSO
  ↓
QWENRNS runtime
```

## Ограничение

EFSO проверяет QWENRNS exhaustively только для формально определённых конечных подпространств.

QWENRNS не доказывает exhaustiveness EFSO.

## Критерий

R4, R5, R6, R7 и NumPy float64 успешно квалифицируют EFSO в пределах заявленных finite spaces и comparison policies.

```text
E11 = PASS
```

# Правила движения

1. Следующий этап не считается закрытым без фактической проверки.
2. Exhaustive означает только полное покрытие явно определённого конечного пространства.
3. Независимость определяется архитектурой зависимости и самостоятельностью реализации, а не языком программирования.
4. R4, R5, R6, R7 и NumPy float64 являются внешними qualification witnesses и не являются runtime-зависимостями EFSO.
5. Отдельный C `float64` oracle не вводится, пока существующий NumPy float64 contour покрывает требуемую qualification axis.
6. `float64` не трактуется как exact real arithmetic.
7. Приоритет имеет точное конечное сравнение там, где оно математически доступно.
8. Любое расхождение должно порождать воспроизводимый counterexample.
9. EFSO не должен превращаться в копию IUT или external reference.
10. Документированное покрытие и evidence являются частью самого oracle, а не внешним приложением.
11. Structural correctness и numerical conformance должны быть представлены раздельно.
12. Qualification PASS не означает доказательство универсальности EFSO за пределами явно определённого finite state space.
